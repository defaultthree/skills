# RDS SQL变更执行流程

## 背景说明

为规范数据库变更操作，确保变更的可追溯性和安全性，SQL变更流程从原有的**堡垒机直接执行**方式，调整为通过**DBW（Database Workbench）工作台提交工单**的方式进行。

### 变更原因

- **安全性提升**：工单审批机制可以防止误操作和高危SQL执行
- **可追溯性**：所有变更记录留存，便于问题排查和审计
- **风险控制**：支持SQL预检查、影响行数评估、锁定时长预估等
- **协同管理**：多人审批流程，确保变更经过充分评估

---

## 工单流程图

```
提交工单 → SQL预检查 → 审核审批 → 执行变更 → 执行结果确认
```

---

## 一、提交工单

### 1. 打开DBW工作台

- **搜索方式**：在火山引擎控制台搜索 `dbw`
- **直接访问**：https://console.volcengine.com/dbw/region:dbw+cn-beijing/

### 2. 创建工单

导航路径：**数据管理 → 工单列表 → 创建工单**

### 3. 填写工单信息

#### 3.1 基本信息

| 字段 | 说明 |
|------|------|
| **工单标题** | 简洁明确地描述变更目的，如：`修复用户表索引缺失问题` |
| **数据库类型** | 选择对应的数据库类型（MySQL/PostgreSQL/Redis等） |
| **实例/数据库** | 选择需要变更的具体实例和数据库名称 |

#### 3.2 工单类型选择

| 工单类型 | 适用场景 | 官方文档 |
|---------|---------|---------|
| **普通SQL变更** | 非热表且数据量小(<10w)，或新建表 | [文档链接](https://www.volcengine.com/docs/6956/1217304) |
| **无锁数据变更** | 数据量大(>10w)的数据修改操作 | [文档链接](https://www.volcengine.com/docs/6956/1217693) |
| **无锁结构变更** | 数据量大(>10w)的表结构变更 | [文档链接](https://www.volcengine.com/docs/6956/1217305) |

**选择建议：**

- **数据变更（UPDATE/INSERT/DELETE）**
  - 数据量 < 10万 → 普通SQL变更
  - 数据量 ≥ 10万 → 无锁数据变更
  
- **结构变更（ALTER TABLE/CREATE INDEX）**
  - 非热表 + 数据量 < 10万 → 普通SQL变更
  - 热表 或 数据量 ≥ 10万 → 无锁结构变更

#### 3.3 执行命令

- 填写完整的SQL语句
- **建议**：一条语句仅操作一个表
- **避免**：复杂的级联查询更新操作
- **建议**：添加必要的WHERE条件和LIMIT限制

**示例：**

```sql
-- 数据更新示例
UPDATE user_info 
SET status = 1 
WHERE id IN (1001, 1002, 1003);

-- 索引创建示例
CREATE INDEX idx_user_create_time 
ON user_info(create_time);

-- 字段添加示例
ALTER TABLE user_info 
ADD COLUMN last_login_time DATETIME DEFAULT NULL 
COMMENT '最后登录时间';
```

#### 3.4 执行方式

| 执行方式 | 说明 | 适用场景 |
|---------|------|---------|
| **自动执行** | 审批通过后立即执行 | 紧急修复、低峰期可立即执行的变更 |
| **手动执行** | 审批通过后，由操作人手动触发执行 | 需要配合其他操作的变更 |
| **定时执行** | 指定未来某个时间点执行 | 业务低峰期执行的计划变更 |

#### 3.5 备注说明

- **变更原因**：简要说明为什么要进行此变更
- **影响范围**：预估影响的数据量和表
- **回滚方案**：如变更出现问题，如何回滚（如有）

---

## 二、SQL预检查

提交工单后，DBW会自动进行SQL预检查：

- ✅ **语法检查**：SQL语法是否正确
- ✅ **规范检查**：是否符合SQL规范（如是否有WHERE条件等）
- ✅ **影响评估**：预估影响行数
- ✅ **性能评估**：预估执行时长和锁定时长
- ⚠️ **风险提示**：高危操作告警（如全表更新、大批量删除等）

**如果预检查不通过，需要修改SQL后重新提交。**

---

## 三、审核工单

### 1. 审批流程

工单提交后会进入审批流程，通常包括：

1. **DBA审核**：数据库管理员审核SQL的安全性和合理性
2. **业务审核**：相关业务负责人确认变更必要性
3. **运维审核**：运维人员确认执行时间和方案

### 2. 审核关注点

审核人员会关注以下方面：

- SQL语句是否规范
- 变更时机是否合适
- 是否有足够的备份
- 回滚方案是否可行
- 是否会对业务造成影响

### 3. 审核结果

- **通过**：工单进入执行阶段
- **驳回**：说明驳回原因，修改后重新提交
- **需补充信息**：补充相关信息后继续审批

---

## 四、执行变更

### 1. 执行前确认

在执行前，请再次确认：

- [ ] SQL语句正确无误
- [ ] 执行时间选择合适（建议业务低峰期）
- [ ] 数据库已有备份
- [ ] 相关业务方已知悉

### 2. 执行过程

- **自动执行**：审批通过后自动执行
- **手动执行**：在工单详情页点击"立即执行"
- **定时执行**：系统在指定时间自动执行

### 3. 执行监控

执行过程中可以在工单详情页查看：

- 执行状态（执行中/已完成/失败）
- 执行进度
- 影响行数
- 执行耗时

---

## 五、执行结果确认

### 1. 成功情况

- 查看执行结果，确认影响行数
- 验证数据变更是否符合预期
- 关闭工单

### 2. 失败情况

- 查看错误日志
- 分析失败原因
- 修正SQL后重新提交工单
- 必要时联系DBA协助处理

---

## 注意事项

### ⚠️ 重要提醒

1. **禁止直接通过堡垒机执行SQL**：所有变更必须通过DBW工单流程
2. **生产环境变更必须审批**：开发、测试环境可以简化流程
3. **大批量变更需分批执行**：避免长时间锁表影响业务
4. **务必在低峰期执行**：减少对业务的影响
5. **先在测试环境验证**：确保SQL正确后再在生产环境执行

### 📋 最佳实践

1. **添加WHERE条件**：避免全表更新或删除
2. **使用LIMIT限制**：大批量操作分批进行
3. **添加注释**：在SQL中添加注释说明用途
4. **保留原始数据**：重要数据变更前先备份
5. **避免高峰期执行**：选择凌晨或业务低峰期

### 🔍 常见问题

**Q1: 紧急SQL如何快速执行？**

A: 可以在工单中标注"紧急"，并在备注中说明紧急原因，审批人会优先处理。

**Q2: 如何查看历史工单？**

A: 数据管理 → 工单列表，可以按时间、状态、创建人等条件筛选。

**Q3: 工单审批超时怎么办？**

A: 可以在工单详情页催办，或直接联系审批人。

**Q4: 执行失败后如何处理？**

A: 查看错误日志定位问题，修正后重新提交工单，或联系DBA协助。

**Q5: 无锁变更和普通变更有什么区别？**

A: 无锁变更采用在线DDL技术，不会长时间锁表，适合大表操作；普通变更会锁表，只适合小表。
